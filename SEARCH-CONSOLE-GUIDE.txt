Google Search Console — japansacred.com 설정 안내

대상 공개 주소: https://www.japansacred.com/
사이트맵: https://www.japansacred.com/sitemap.xml

현재 원본은 실제 사용 중인 www 도메인을 기준으로 12개 페이지의 canonical, hreflang, Open Graph, 구조화 데이터와 사이트맵을 설정합니다. GitHub Pages에서 도메인을 연결한 상태를 유지하고 기존 CNAME 파일은 삭제하지 마세요.

1. 이 폴더의 수정된 HTML 12개, index.js, sitemap.xml, robots.txt 및 나머지 사이트 파일을 함께 GitHub Pages 게시 폴더에 업로드합니다. 기존 .git, CNAME, 도메인 설정, Search Console 소유권 확인 파일은 지우지 마세요. GitHub Desktop에서 Commit 후 Push가 완료되어야 실제 사이트에 적용됩니다.
2. 배포 후 https://www.japansacred.com/sitemap.xml 을 열어 12개 주소가 모두 https://www.japansacred.com/으로 시작하는지 확인하세요. 현재 공개된 이전 사이트맵은 기존 GitHub 주소가 들어 있을 수 있습니다. robots.txt도 https://www.japansacred.com/robots.txt 에서 열리는지 확인하세요.
3. Search Console의 https://www.japansacred.com/ URL 접두어 속성을 선택하고 사이트맵 메뉴에 sitemap.xml을 다시 제출하세요. 기존 오류 표시가 즉시 사라지지 않을 수 있습니다. Google 재처리를 기다리고 마지막 읽은 날짜와 상태를 확인하세요. 소유권이 확인되지 않았다면 Google이 안내하는 절차를 직접 완료해야 합니다.
4. 오류가 남으면 해당 사이트맵을 눌러 정확한 오류 유형과 예시 URL을 확인하세요. URL 검사 도구로 홈페이지와 일본어·영어 페이지의 실제 URL 테스트를 진행합니다. 사이트맵 제출은 색인을 보장하지 않습니다.

중요: robots.txt는 https://www.japansacred.com/robots.txt 처럼 호스트 루트에 있어야 합니다. 현재 원본의 robots.txt는 사용자 지정 도메인이 GitHub Pages의 게시 루트에 연결되어 있다는 전제입니다. 저장소를 다른 서버 하위 경로에 배포하는 경우 루트 설정을 다시 확인해야 합니다.

유지보수: CSS/JS를 변경하면 각 HTML의 ?v= 해시도 갱신해 함께 배포하세요. 세 언어별 URL은 별개이며, 30개 장소는 현재 독립 페이지가 아니라 장소 안내 페이지의 앵커입니다. 중국어 페이지와 애드센스 코드는 추가하지 않았습니다.
